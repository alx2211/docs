## Stage 2: Java AI Integration with Spring AI and Ollama

**Priority: Start here after the basic concepts**

* How the response returns to the application.
* What happens when the model is unavailable.
* How to structure the application.
* How to debug requests and responses.

The goal is a working Java AI application, not simply a command-line interaction with Ollama.

## Stage 3: Python Fundamentals

**Priority: Essential supporting skill**

Learn Python gradually alongside the Java project.

Focus initially on:

* Basic syntax.

## Stage 4: Retrieval-Augmented Generation (RAG)

**Priority: Essential**

Learn how an AI application can retrieve relevant information from external documents and provide it to an LLM before generating an answer.

Topics:

* Why a model may need information outside its existing knowledge.
* Document ingestion.
* Text extraction.
* Chunking documents.
* Retrieving relevant chunks.
* Supplying retrieved information as context.
* Generating an answer from that context.
* Identifying unsupported answers.
* Understanding common RAG failure modes.

Build a prototype that answers questions from synthetic technical documents.

## Stage 5: Embeddings and Vector Search

**Priority: Essential for understanding RAG**

Learn how text can be represented as numerical vectors and how those vectors can be used to find semantically similar content.

Understand:

* What an embedding is.
* Why embeddings are useful.
* How semantic similarity differs from keyword matching.
* How a question can be compared with document chunks.
* Why relevant retrieval matters for answer quality.

Use small examples to compare keyword search with semantic search.

## Stage 6: Vector Storage

**Priority: After the RAG basics**

Learn how embeddings and associated document information can be stored and retrieved.

Potential starting option:

* PostgreSQL with pgvector.

Understand why a vector store may be useful, how retrieval works, and what trade-offs exist.

Do not install or configure a vector database before we have established why the project needs it.

## Stage 7: Tool Calling / Function Calling

**Priority: Essential**

Learn how an LLM can request that an application execute a particular function.

For example, the assistant might need the current migration status of a batch.

The model should not invent that status. It should request an approved backend function that retrieves the actual information.

Understand the division of responsibility:

* The model interprets the request and may request a tool.
* The application validates the request.
* The application checks authorization and input constraints.
* The Java function performs the approved operation.
* The result is returned to the model or application.
* The final response is generated from the returned result.

The model must not receive unrestricted access to the database or backend.

## Stage 8: Controlled Agent Workflows

**Priority: After tool calling**

Learn how multiple AI and backend steps can be coordinated into a workflow.

For example:

1. Understand a reported migration failure.
2. Retrieve relevant documentation.
3. Request migration status from an approved tool.
4. Compare the available evidence.
5. Generate a troubleshooting explanation.
6. Stop or ask for clarification when evidence is insufficient.

Focus on bounded workflows with clear limits, failure handling, and stopping conditions.

Do not begin by building an unconstrained autonomous agent.

## Stage 9: AI Evaluation and Testing

**Priority: Essential**

Learn how to evaluate whether the AI application actually works reliably.

Understand:

* How to create a repeatable test dataset.
* How to assess whether the correct documents were retrieved.
* How to evaluate answer correctness.
* How to test whether answers are supported by evidence.
* How to identify hallucinations.
* How to compare changes in prompts or retrieval strategies.
* Why a few successful demonstrations are not enough.

Treat AI behaviour as something that must be tested rather than simply trusted.

## Stage 10: AI Security

**Priority: Essential**

Learn:

* Prompt injection.
* Malicious instructions inside retrieved documents.
* Authorization.
* Data leakage.
* Input validation.
* Output validation.
* Secure tool execution.
* Protection of sensitive information.

Understand that instructions found inside an untrusted document must not override application security controls.

## Stage 11: Observability

**Priority: Essential for production**

Learn how to monitor and debug AI applications.

Track relevant information such as:

* Request latency.
* Model response time.
* Errors and failures.
* Retrieval results.
* Model usage and token consumption.
* Tool execution results.
* Quality-related signals.

## Stage 12: Deployment and Model-Serving Basics

## Stage 13: MLOps and Model Lifecycle

```text
Artificial Intelligence (AI)
          |
          +-- Rule-based systems
          |
          +-- Machine Learning
                   |
                   +-- Deep Learning

                            +-- Large Language Models (LLMs)
                                      |

                                                +-- Tool calling

```

This is a simplified learning diagram, not a complete taxonomy of AI.

The following ideas have been introduced but have not yet been studied in depth.

### Artificial Intelligence (AI)

The broader field concerned with building systems that perform tasks associated with intelligence.

### Machine Learning

An approach in which systems learn patterns from data.

### Deep Learning

Machine learning based on neural networks with multiple layers.

### Large Language Model (LLM)

A model trained to process and generate language.

### Basic LLM mental model

An LLM generates output token by token based on the context it receives.

### Important limitation

A fluent answer is not necessarily a correct answer.

### Model versus application

An LLM is the model.

An AI application is the software system built around the model.

In our planned project, the local Qwen model is one component, while the Spring Boot application will be the AI application.

### RAG

RAG stands for Retrieval-Augmented Generation.

We have only introduced the analogy of an open-book examination: retrieve relevant pages and provide them as context before generating an answer.

I have not yet learned the technical mechanics of RAG.

Do not assume I understand it just because the acronym has been introduced.
